## Introduction

Bienvenue dans ce guide de démarrage rapide consacré à **Stripe Billing** dans une application SaaS Next.js.

L’objectif est de mettre en place une intégration simple, sécurisée et maintenable avec :

- une page de tarifs ;
- Stripe Checkout pour souscrire à un abonnement ;
- un webhook signé pour synchroniser l’état de l’abonnement ;
- le portail client Stripe pour gérer la facturation ;
- une protection serveur des fonctionnalités payantes.

Le guide utilise **Stripe Checkout hébergé par Stripe**. Cette solution réduit la quantité de code de paiement à maintenir et permet de bénéficier directement des moyens de paiement, de l’authentification forte et des évolutions de Checkout.

> La page de succès améliore l’expérience utilisateur, mais elle ne doit jamais être utilisée comme preuve de paiement. Les webhooks Stripe restent la source de vérité pour activer ou retirer les droits d’accès.

## Stack Technique

- **Next.js 15+** avec App Router ;
- **TypeScript** ;
- **Stripe Checkout** pour la souscription ;
- **Stripe Billing** pour les abonnements ;
- **Stripe Customer Portal** pour la gestion de la facturation ;
- **Auth.js** pour l’authentification dans les exemples ;
- **Prisma** pour la persistance dans les exemples ;
- **shadcn/ui** pour l’interface ;
- **Vercel** pour le déploiement, recommandé mais facultatif.

Les parties Auth.js et Prisma peuvent être adaptées à un autre système d’authentification ou à un autre ORM.

## Architecture de l’Intégration

```text
Utilisateur authentifié
        │
        ▼
Page /pricing
        │ POST /api/stripe/checkout
        ▼
Stripe Checkout
        │
        ├── redirection UX ──► /dashboard/billing?success=1
        │
        └── événements signés ──► /api/stripe/webhook
                                      │
                                      ▼
                              Mise à jour de la base
                                      │
                                      ▼
                              Droits d’accès SaaS

Utilisateur authentifié
        │
        ▼
POST /api/stripe/portal
        │
        ▼
Stripe Customer Portal
```

## 📋 Prérequis et Installation

```bash

Un projet Next.js avec App Router
Un compte Stripe
Une authentification utilisateur
Une base de données
```

Pour la production, votre application doit être accessible avec une URL HTTPS publique afin que Stripe puisse joindre le webhook.

```bash
pnpm add @prisma/client
pnpm add -D prisma
```

Initialiser Prisma si nécessaire :


## 3. Configurer les Produits et les Prix dans Stripe

Dans le Dashboard Stripe, activez l’environnement de test ou utilisez un sandbox, puis créez :

1. un produit, par exemple **Pro** ;
2. un prix mensuel récurrent ;
3. éventuellement un prix annuel récurrent.

Chaque prix possède un identifiant qui commence par `price_`.

Exemple :

```text
Produit : Pro
Prix mensuel : price_123_monthly
Prix annuel : price_456_yearly
```

Ne saisissez pas directement les montants dans le code de création de l’abonnement. Utilisez les identifiants de prix Stripe afin que le Dashboard reste la référence du catalogue.

### 3.1 Configurer le portail client

Dans les réglages Stripe Billing, configurez le **Customer Portal** pour autoriser les actions souhaitées :

- mise à jour du moyen de paiement ;
- consultation des factures ;
- changement d’offre ;
- résiliation de l’abonnement ;
- collecte éventuelle d’un motif de résiliation.

Testez cette configuration avant de l’activer en production.

## 4. Variables d’Environnement

Créez ou complétez le fichier `.env` :

```bash
# URL canonique de l'application
APP_URL=http://localhost:3000

# Clé API secrète Stripe du sandbox ou du mode test
STRIPE_SECRET_KEY=sk_test_xxxxxxxxxxxxxxxxxxxxx

# Secret de signature du webhook local ou distant
STRIPE_WEBHOOK_SECRET=whsec_xxxxxxxxxxxxxxxxxxxxx

# Prix autorisés par l'application
STRIPE_PRICE_PRO_MONTHLY=price_xxxxxxxxxxxxxxxxxxxxx
STRIPE_PRICE_PRO_YEARLY=price_xxxxxxxxxxxxxxxxxxxxx
```

### Règles de sécurité

- Ne préfixez jamais `STRIPE_SECRET_KEY` ou `STRIPE_WEBHOOK_SECRET` avec `NEXT_PUBLIC_`.
- Ne commitez jamais le fichier `.env`.
- Utilisez des secrets distincts entre test et production.
- Un secret de webhook appartient à un endpoint précis. Le secret généré par Stripe CLI est différent de celui configuré dans le Dashboard.
- Les identifiants `price_` ne sont pas secrets, mais ils doivent tout de même être validés côté serveur.

## 8. Ajouter les Données Stripe dans Prisma

L’exemple ci-dessous suppose que le modèle `User` existe déjà.

Mettez à jour **`prisma/schema.prisma`** en fusionnant les champs suivants avec votre schéma :

```prisma
model User {
  id               String        @id @default(cuid())
  email            String        @unique
  stripeCustomerId String?       @unique
  subscriptions    Subscription[]

  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
}

model Subscription {
  id                 String   @id
  userId             String
  stripeCustomerId   String
  status             String
  priceId            String?
  productId          String?
  currentPeriodStart DateTime?
  currentPeriodEnd   DateTime?
  cancelAtPeriodEnd  Boolean  @default(false)

  user User @relation(fields: [userId], references: [id], onDelete: Cascade)

  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@index([userId, status])
  @@index([stripeCustomerId])
}

model StripeEvent {
  id        String   @id
  type      String
  createdAt DateTime @default(now())
}
```

Appliquez la migration :

```bash
pnpm prisma migrate dev --name add_stripe_billing
pnpm prisma generate
```

Le modèle `StripeEvent` sert à rendre le traitement des webhooks idempotent. Stripe peut renvoyer un événement lorsqu’un endpoint ne répond pas correctement ou lors d’une nouvelle tentative manuelle. Le modèle `Subscription` conserve une ligne par abonnement Stripe, ce qui permet de gérer proprement une résiliation suivie d’une nouvelle souscription.

## 10. Créer un Adaptateur d’Authentification

L’intégration Stripe doit toujours relier une action de facturation à un utilisateur authentifié.

Créez **`src/lib/billing-user.ts`** :

```ts
import "server-only";

import { auth } from "@/auth";
import { prisma } from "@/lib/prisma";

export async function requireBillingUser() {
  const session = await auth();

  if (!session?.user?.id || !session.user.email) {
    throw new Error("UNAUTHORIZED");
  }

  const user = await prisma.user.findUnique({
    where: { id: session.user.id },
    include: {
      subscriptions: {
        orderBy: { updatedAt: "desc" },
      },
    },
  });

  if (!user) {
    throw new Error("USER_NOT_FOUND");
  }

  return user;
}
```

Adaptez cette fonction si vous utilisez Clerk, Supabase Auth, Firebase Auth ou une authentification personnalisée.

## 11. Créer ou Réutiliser un Customer Stripe

Un utilisateur de l’application doit idéalement être associé à un seul objet `Customer` Stripe.

Créez **`src/lib/stripe-customer.ts`** :

```ts
import "server-only";

import { prisma } from "@/lib/prisma";
import { stripe } from "@/lib/stripe";

type BillingUser = {
  id: string;
  email: string;
  stripeCustomerId: string | null;
};

export async function getOrCreateStripeCustomer(
  user: BillingUser,
): Promise<string> {
  if (user.stripeCustomerId) {
    return user.stripeCustomerId;
  }

  const customer = await stripe.customers.create(
    {
      email: user.email,
      metadata: {
        userId: user.id,
      },
    },
    {
      idempotencyKey: `customer:${user.id}`,
    },
  );

  await prisma.user.update({
    where: { id: user.id },
    data: { stripeCustomerId: customer.id },
  });

  return customer.id;
}
```

La métadonnée `userId` facilite le rapprochement entre Stripe et votre base de données. Elle ne remplace pas l’authentification et ne doit contenir aucune donnée sensible.

## 12. Créer l’Endpoint Stripe Checkout

Créez **`src/app/api/stripe/checkout/route.ts`** :

```ts
import { NextResponse } from "next/server";

import { requireBillingUser } from "@/lib/billing-user";
import { env } from "@/lib/env";
import { isAllowedPriceId } from "@/lib/plans";
import { stripe } from "@/lib/stripe";
import { getOrCreateStripeCustomer } from "@/lib/stripe-customer";

export const runtime = "nodejs";

const blockedSubscriptionStatuses = new Set([
  "active",
  "trialing",
  "past_due",
  "unpaid",
  "incomplete",
  "paused",
]);

export async function POST(request: Request) {
  try {
    const user = await requireBillingUser();

    if (
      user.subscriptions.some((subscription) =>
        blockedSubscriptionStatuses.has(subscription.status),
      )
    ) {
      return NextResponse.redirect(
        new URL("/dashboard/billing?alreadySubscribed=1", env.APP_URL),
        303,
      );
    }

    const formData = await request.formData();
    const priceId = formData.get("priceId");

    if (typeof priceId !== "string" || !isAllowedPriceId(priceId)) {
      return NextResponse.json(
        { error: "Identifiant de prix invalide." },
        { status: 400 },
      );
    }

    const customerId = await getOrCreateStripeCustomer(user);

    const checkoutSession = await stripe.checkout.sessions.create({
      mode: "subscription",
      customer: customerId,
      client_reference_id: user.id,
      line_items: [
        {
          price: priceId,
          quantity: 1,
        },
      ],
      success_url: `${env.APP_URL}/dashboard/billing?success=1`,
      cancel_url: `${env.APP_URL}/pricing?canceled=1`,
      allow_promotion_codes: true,
      billing_address_collection: "auto",
      customer_update: {
        address: "auto",
        name: "auto",
      },
      metadata: {
        userId: user.id,
      },
      subscription_data: {
        metadata: {
          userId: user.id,
        },
      },
    });

    if (!checkoutSession.url) {
      throw new Error("CHECKOUT_URL_MISSING");
    }

    return NextResponse.redirect(checkoutSession.url, 303);
  } catch (error) {
    console.error("[STRIPE_CHECKOUT]", error);

    if (error instanceof Error && error.message === "UNAUTHORIZED") {
      return NextResponse.redirect(new URL("/login", env.APP_URL), 303);
    }

    return NextResponse.json(
      { error: "Impossible de créer la session de paiement." },
      { status: 500 },
    );
  }
}
```

### Pourquoi utiliser un POST ?

La création d’une Checkout Session est une mutation côté serveur. Elle ne doit pas être déclenchée avec une URL GET partageable ou préchargeable.

### Pourquoi valider le prix côté serveur ?

Le contenu d’un formulaire peut être modifié par l’utilisateur. Le serveur doit donc refuser tout identifiant `priceId` qui n’appartient pas au catalogue autorisé.

## 14. Synchroniser les Abonnements

Créez **`src/lib/sync-stripe-subscription.ts`** :

```ts
import type { Prisma } from "@prisma/client";
import type Stripe from "stripe";

export async function syncStripeSubscription(
  tx: Prisma.TransactionClient,
  subscription: Stripe.Subscription,
) {
  const customerId =
    typeof subscription.customer === "string"
      ? subscription.customer
      : subscription.customer.id;

  const userFromCustomer = await tx.user.findUnique({
    where: { stripeCustomerId: customerId },
    select: { id: true },
  });

  const userId = subscription.metadata.userId ?? userFromCustomer?.id;

  if (!userId) {
    throw new Error(
      `Utilisateur introuvable pour l'abonnement ${subscription.id}`,
    );
  }

  const subscriptionItem = subscription.items.data[0];
  const price = subscriptionItem?.price;

  const productId = price
    ? typeof price.product === "string"
      ? price.product
      : price.product.id
    : null;

  await tx.user.update({
    where: { id: userId },
    data: { stripeCustomerId: customerId },
  });

  await tx.subscription.upsert({
    where: { id: subscription.id },
    create: {
      id: subscription.id,
      userId,
      stripeCustomerId: customerId,
      status: subscription.status,
      priceId: price?.id ?? null,
      productId,
      currentPeriodStart: subscriptionItem?.current_period_start
        ? new Date(subscriptionItem.current_period_start * 1000)
        : null,
      currentPeriodEnd: subscriptionItem?.current_period_end
        ? new Date(subscriptionItem.current_period_end * 1000)
        : null,
      cancelAtPeriodEnd: subscription.cancel_at_period_end,
    },
    update: {
      userId,
      stripeCustomerId: customerId,
      status: subscription.status,
      priceId: price?.id ?? null,
      productId,
      currentPeriodStart: subscriptionItem?.current_period_start
        ? new Date(subscriptionItem.current_period_start * 1000)
        : null,
      currentPeriodEnd: subscriptionItem?.current_period_end
        ? new Date(subscriptionItem.current_period_end * 1000)
        : null,
      cancelAtPeriodEnd: subscription.cancel_at_period_end,
    },
  });
}
```

La synchronisation utilise la première ligne d’abonnement. Pour un modèle contenant plusieurs produits ou plusieurs quantités, adaptez le schéma afin d’enregistrer tous les `subscription.items`.

## 15. Créer le Webhook Stripe

Créez **`src/app/api/stripe/webhook/route.ts`** :

```ts
import type Stripe from "stripe";

import { env } from "@/lib/env";
import { prisma } from "@/lib/prisma";
import { stripe } from "@/lib/stripe";
import { syncStripeSubscription } from "@/lib/sync-stripe-subscription";

export const runtime = "nodejs";
export const dynamic = "force-dynamic";

export async function POST(request: Request) {
  const signature = request.headers.get("stripe-signature");

  if (!signature) {
    return new Response("Signature Stripe absente.", { status: 400 });
  }

  const rawBody = await request.text();

  let event: Stripe.Event;

  try {
    event = stripe.webhooks.constructEvent(
      rawBody,
      signature,
      env.STRIPE_WEBHOOK_SECRET,
    );
  } catch (error) {
    console.error("[STRIPE_WEBHOOK_SIGNATURE]", error);
    return new Response("Signature Stripe invalide.", { status: 400 });
  }

  try {
    await prisma.$transaction(async (tx) => {
      const alreadyProcessed = await tx.stripeEvent.findUnique({
        where: { id: event.id },
        select: { id: true },
      });

      if (alreadyProcessed) {
        return;
      }

      switch (event.type) {
        case "checkout.session.completed": {
          const session = event.data.object as Stripe.Checkout.Session;
          const userId = session.metadata?.userId;
          const customerId =
            typeof session.customer === "string"
              ? session.customer
              : session.customer?.id;

          if (userId && customerId) {
            await tx.user.update({
              where: { id: userId },
              data: { stripeCustomerId: customerId },
            });
          }

          break;
        }

        case "customer.subscription.created":
        case "customer.subscription.updated":
        case "customer.subscription.deleted": {
          const subscription = event.data.object as Stripe.Subscription;
          await syncStripeSubscription(tx, subscription);
          break;
        }

        case "invoice.payment_failed": {
          // Ajouter ici une notification email ou une alerte dans l'application.
          console.warn("Paiement de facture échoué", {
            eventId: event.id,
          });
          break;
        }

        default: {
          console.info(`Événement Stripe ignoré : ${event.type}`);
        }
      }

      await tx.stripeEvent.create({
        data: {
          id: event.id,
          type: event.type,
        },
      });
    });

    return Response.json({ received: true });
  } catch (error) {
    console.error("[STRIPE_WEBHOOK_PROCESSING]", error);

    // Retourner 500 permet à Stripe de retenter l'envoi.
    return new Response("Erreur de traitement du webhook.", { status: 500 });
  }
}
```

### Points importants

- Utilisez `request.text()` afin de vérifier la signature sur le corps brut.
- Ne parsez pas le JSON avant `constructEvent()`.
- Traitez les événements de manière idempotente.
- Répondez rapidement avec un code `2xx` après un traitement réussi.
- Retournez une erreur serveur si le traitement métier échoue afin que Stripe puisse effectuer une nouvelle tentative.
- N’enregistrez jamais les données complètes de paiement ou les numéros de carte dans votre base.

### Événements recommandés

Configurez au minimum les événements suivants :

```text
checkout.session.completed
customer.subscription.created
customer.subscription.updated
customer.subscription.deleted
invoice.payment_failed
```

Vous pouvez également gérer :

```text
invoice.paid
invoice.payment_action_required
customer.subscription.trial_will_end
```

Le choix dépend de votre politique d’accès, de relance et de période d’essai.

## 16. Créer l’Endpoint du Portail Client

Créez **`src/app/api/stripe/portal/route.ts`** :

```ts
import { NextResponse } from "next/server";

import { requireBillingUser } from "@/lib/billing-user";
import { env } from "@/lib/env";
import { stripe } from "@/lib/stripe";

export const runtime = "nodejs";

export async function POST() {
  try {
    const user = await requireBillingUser();

    if (!user.stripeCustomerId) {
      return NextResponse.redirect(
        new URL("/pricing?customerMissing=1", env.APP_URL),
        303,
      );
    }

    const portalSession = await stripe.billingPortal.sessions.create({
      customer: user.stripeCustomerId,
      return_url: `${env.APP_URL}/dashboard/billing`,
    });

    return NextResponse.redirect(portalSession.url, 303);
  } catch (error) {
    console.error("[STRIPE_PORTAL]", error);

    if (error instanceof Error && error.message === "UNAUTHORIZED") {
      return NextResponse.redirect(new URL("/login", env.APP_URL), 303);
    }

    return NextResponse.json(
      { error: "Impossible d'ouvrir le portail de facturation." },
      { status: 500 },
    );
  }
}
```

Le portail doit être ouvert uniquement pour l’utilisateur authentifié lié au `stripeCustomerId`. Ne transmettez jamais un identifiant Customer fourni par le navigateur.

## 18. Protéger les Fonctionnalités Payantes

Créez **`src/lib/subscription-access.ts`** :

```ts
const paidStatuses = new Set(["active", "trialing"]);

type SubscriptionLike = {
  status: string;
};

export function hasPaidAccess(
  subscriptions: SubscriptionLike[],
): boolean {
  return subscriptions.some((subscription) =>
    paidStatuses.has(subscription.status),
  );
}
```

Exemple dans un Server Component :

```tsx
import { redirect } from "next/navigation";

import { requireBillingUser } from "@/lib/billing-user";
import { hasPaidAccess } from "@/lib/subscription-access";

export default async function PremiumPage() {
  const user = await requireBillingUser();

  if (!hasPaidAccess(user.subscriptions)) {
    redirect("/pricing");
  }

  return <div>Contenu réservé aux abonnés.</div>;
}
```

Appliquez également cette vérification dans les Route Handlers et Server Actions sensibles. Masquer un bouton dans l’interface ne constitue pas une protection d’accès.

### Politique pour `past_due`

Deux stratégies sont possibles :

- **stricte** : retirer immédiatement l’accès lorsque le statut n’est plus `active` ou `trialing` ;
- **tolérante** : conserver temporairement l’accès pendant les tentatives de recouvrement.

La fonction `hasPaidAccess()` doit refléter la politique commerciale de votre SaaS.

## 22. Bonnes Pratiques de Sécurité

### Ne jamais faire confiance au navigateur

Le navigateur peut proposer un `priceId`, mais le serveur doit vérifier qu’il appartient à une offre autorisée.

### Ne jamais activer un abonnement depuis la page de succès

Un utilisateur peut ouvrir ou partager une URL. Seul un événement Stripe vérifié doit modifier les droits en base.

### Vérifier systématiquement la signature du webhook

Utilisez le corps brut, l’en-tête `stripe-signature` et le secret de l’endpoint concerné.

### Rendre le traitement idempotent

Un événement peut être livré plusieurs fois. Stockez son identifiant `event.id` afin d’éviter les doubles traitements.

### Prévoir les événements dans le désordre

Un système distribué ne doit pas dépendre d’un ordre parfait de livraison. Les événements d’abonnement contiennent les données nécessaires pour reconstruire l’état courant.

### Utiliser les identifiants internes dans les métadonnées

La métadonnée `userId` permet de rapprocher les objets, mais n’y placez jamais de token, de mot de passe, de donnée bancaire ou d’information confidentielle.

### Séparer les environnements

Utilisez des clés, prix et secrets de webhook distincts entre développement, test et production.
